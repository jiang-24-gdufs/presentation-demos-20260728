Module 02

Entity API

增删改查流程

viewer.entities.add()
→
entities.getById(id)
→
修改 entity.position / 属性
→
entities.remove(entity)

绑定业务属性

通过 entity.properties 挂载自定义键值对（如 ID、状态、类型），拾取时可直接读取，无需额外数据结构映射。

样式配置

支持 point / billboard / label / polygon 等可视化样式，均支持 heightReference 贴地设置。

飞行定位

viewer.zoomTo(entity) 或 viewer.flyTo(entity) 快速定位到目标实体，支持传入 offset 控制视角。

选型决策树：Entity vs Primitive

问：你的场景中需要渲染多少个同类对象？
≤ 100 个
→ 使用 Entity API
代码简洁、支持属性绑定、自动管理生命周期
> 100 个
→ 改用 Primitive API
直接操作 GPU 缓冲、批量渲染、性能提升 10x+
⛔
性能红线：Entity 数量超过 100 后帧率将显著下降。如需展示上千个标注点，务必使用 PointPrimitiveCollection 或 BillboardCollection。

Module 04

调试与体检

核心调试工具

Cesium Inspector

通过 viewer.extend(Cesium.viewerCesium3DTilesInspectorMixin) 开启，可查看 3D Tiles 瓦片加载状态、包围盒、LOD 层级、内存占用。

浏览器 Network 面板

过滤 b3dm / i3dm / terrain 等关键字，观察请求数、响应时间、是否返回 404/CORS 错误。

Console 调试

使用 viewer.entities.values 遍历实体列表；viewer.scene.primitives 查看 Primitive 集合；viewer.camera 获取相机位姿。

常见症状自查表

症状可能原因排查方向
白屏WebGL 上下文丢失检查 GPU 驱动 / 浏览器硬件加速开关
黑屏（无底图）影像服务未响应或 Token 无效Network 面板检查影像 URL 返回状态
模型悬空未设置 heightReference改为 CLAMP_TO_GROUND 或调整高度偏移
模型沉入地下地形精度不匹配检查 modelMatrix 或 heightOffset
跨域错误（CORS）资源服务器未配置 CORS 头服务端添加 Access-Control-Allow-Origin
瓦片闪烁 / 加载慢SSE 设置过小 / 网络瓶颈增大 maximumScreenSpaceError 值
帧率极低Entity 过多 / 未启用按需渲染改用 Primitive + requestRenderMode

Module 05

坐标系统与空间计算

Cesium 中的三种坐标系

坐标系类型表示方式典型用途
WGS84 经纬度 Cartographic 经度 (°) / 纬度 (°) / 高程 (m) GPS 定位、用户输入坐标、地理编码
笛卡尔坐标 Cartesian3 X / Y / Z（米，地心坐标系） Entity 定位、空间距离计算、模型变换
屏幕坐标 Cartesian2 px_x / px_y 鼠标交互、UI 弹窗定位、拾取操作

GIS 行业常用坐标系（EPSG 编码）

EPSG名称类型使用场景
4326 WGS 84 地理坐标（经纬度） GPS 全球标准；Cesium 内部默认坐标系
3857 Web Mercator 投影坐标（米） Google Maps / OSM / 天地图 Web 瓦片；正方形切割，高纬度变形严重
4490 CGCS2000 地理 地理坐标（经纬度） 中国国家标准（天地图、自然资源部），与 WGS84 差异 < 1cm
4548 CGCS2000 / 3°带投影 投影坐标（米） 国土测绘、城市规划、工程测量，iDesktop 制图常用

超图工具链中的坐标系

iDesktop（桌面端制图）

数据入库时设定坐标系。测绘数据常用 CGCS2000 (4490/4548)，互联网数据常用 WGS84 (4326)。坐标系在此阶段确定，后续流程必须一致。

iServer（服务发布）

发布三维服务时可配置动态投影。REST 接口返回的坐标默认与数据源一致，也可在请求参数中指定 prjCoordSys 转换。

Cesium 前端加载

Cesium 内部统一使用 WGS84 + Cartesian3。CGCS2000 (4490) 与 WGS84 (4326) 在实际使用中差异极小（<1cm），可直接当作 4326 使用。

⚠
为什么坐标系这么多？地球不是完美球体，不同地区/行业采用不同的参考椭球和投影方式以获得最佳精度。Web 端统一用 4326（地理）+ 3857（投影），Cesium 三维场景内部全部基于 WGS84。遇到数据偏移时，首先检查数据源和加载端的坐标系是否一致。

核心转换流程

WGS84 经纬度
(lng, lat, alt)
⇄
Cartesian3 笛卡尔
(x, y, z)
⇄
屏幕坐标
(px, py)

关键转换 API

经纬度 → Cartesian3

Cesium.Cartesian3.fromDegrees(lng, lat, alt)

最常用的转换，创建 Entity 时必用。

Cartesian3 → 经纬度

Cesium.Cartographic.fromCartesian(cartesian)

返回弧度值，需配合 Math.toDegrees() 转角度。

屏幕 → 世界坐标

scene.pickPosition(screenPos)

camera.pickEllipsoid(screenPos)

前者考虑地形/模型深度，后者仅椭球面。

世界坐标 → 屏幕

SceneTransforms.wgs84ToWindowCoordinates(scene, cartesian)

用于在 3D 对象上方叠加 HTML 弹窗。

⛔
最常见的坑：Cartesian3.fromDegrees() 参数顺序是 (经度, 纬度, 高度)，不是 (纬度, 经度)！搞反了东西就会"放歪"——中国的点会跑到大西洋上。
💡
坐标转换 API（Cartesian3、Cartographic、Math）属于 Cesium 核心模块，CDN 版和超图版均可使用，无版本差异。

坐标怎么转？

经纬度 ⇄ Cartesian3 ⇄ 屏幕坐标
fromDegrees 参数是 (经度, 纬度)，别搞反了
