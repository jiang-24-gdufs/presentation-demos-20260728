Module 01

搭建三维地球底座

Cesium 能加载哪些数据？答案是：几乎所有主流空间数据格式。

建立"看到一种数据格式，就知道该用哪个 API 加载"的直觉。

先理清两个基础：地形与影像

地形（Terrain）— 地球的几何骨架

地形数据定义地表的高程起伏（DEM），让原本光滑的数学椭球面变得有山有谷。没有地形时，地球是一个标准球体。

作用：提供几何形状（高度信息）。

影像（Imagery）— 地表的纹理贴图

影像数据是覆盖在地形表面上的栅格图片瓦片（卫星图、路网图等），让地球表面拥有颜色和细节。影像本身不包含高度。

作用：提供外观纹理（视觉信息）。

最终效果 = 椭球体基底 + 地形高程（几何） + 影像纹理（外观），三者叠加形成你看到的三维地球。

Module 02

在地球上绘制业务元素

加载完底图只是第一步，真正的业务价值体现在你"画上去"的那些标注、区域、轨迹上。Entity API 是 Cesium 提供的高层封装接口，用来快速创建和管理可视化对象。

增删改查的标准流程

viewer.entities.add()
→
entities.getById(id)
→
修改 entity.position / 样式属性
→
entities.remove(entity)

绑定业务属性

通过 entity.properties 挂载任意自定义键值对（如设备ID、状态、类型），拾取时可直接读取，无需额外维护映射表。

丰富的可视化样式

支持 point（点）、billboard（图标）、label（文字标签）、polygon（面）等多种图形，均可设置 heightReference 实现贴地或固定高度。

快速定位与飞行

viewer.zoomTo(entity) 或 viewer.flyTo(entity) 可一键将相机聚焦到目标实体，支持传入偏移量控制观看角度。

典型业务场景中的 Entity 应用

IoT 设备监控

用 billboard 展示设备图标，label 显示实时状态（正常/告警/离线），通过 properties 挂载设备ID和上报时间。点击后弹出详情面板，颜色可随状态动态变化。

管线 / 路径可视化

用 polyline 绘制管线或路径，搭配 label 标注名称和材质。可通过 PolylineGlowMaterialProperty 添加发光流动效果，模拟介质流向。

区域围栏与地块划分

用 polygon + 半透明填充绘制地块边界，同时用 polyline 描边高亮。适用于城市规划、应急管理中的区域标注。

轨迹回放

结合 SampledPositionProperty 实现按时间轴驱动的位置动画，适合车辆 GPS 轨迹、无人机航迹回放。配合 PathGraphics 可显示历史路径。

Entity vs Primitive 对比

对比维度Entity APIPrimitive API
抽象层级高层封装，面向业务对象底层接口，面向渲染管线
性能上限适合 < 100 个对象轻松支撑数千~数万个对象
属性绑定内置 properties，直接挂载业务数据无内置属性，需自行维护外部映射
拾取支持scene.pick 直接返回 Entity 引用返回 Primitive 引用，需额外处理
动画/时间轴内置 SampledProperty，与 Cesium 时钟联动需在 preRender 回调中手动更新
典型 APIviewer.entities.add()scene.primitives.add(new PointPrimitiveCollection())
适用场景标注点、InfoBox、轨迹回放、区域绘制热力图、大规模标注、粒子系统、自定义着色器
⚠
Entity 内部是对 Primitive 的封装，数量少时方便好用，但超过 100 个时帧率明显下降。对于大批量标注，建议直接使用 PointPrimitiveCollection 等 Primitive 方式。

Module 03

点击查询属性

用户点击三维场景中的物体，如何知道点中了什么？如何弹出对应的业务信息？scene.pick() 是入口，但你需要根据拾取对象的类型（Entity / 3D Tiles 要素 / 空白区域）走不同的分支。

点击拾取标准流程

注册鼠标事件
ScreenSpaceEventHandler
→
执行场景拾取
scene.pick(position)
→
判断拾取类型
Entity / Cesium3DTileFeature / 其他
→
业务处理
弹窗 / 高亮 / 调用后端

拾取分支判断详解

Entity 拾取

判断条件：picked.id instanceof Cesium.Entity

读取属性：entity.properties.getValue()

适用场景：点标注、自定义图标、路径对象等。

模型（glTF）拾取

加载方式：通过 Entity + model 或 Model.fromGltf 加载的 3D 模型。

拾取后同样返回 Entity，可通过 entity.model 判断是否为模型。

适用场景：单体建筑、设备模型等精细模型挂载的属性查询。

3D Tiles 要素拾取

判断条件：picked instanceof Cesium3DTileFeature

读取属性：通过 feature.getProperty(name) 获取批量属性表中的字段。

适用场景：倾斜摄影建筑、BIM 构件、管线等大规模瓦片数据。

根据坐标查询倾斜摄影

输入经纬度 → 相机飞行定位到该点 → 使用屏幕中心点拾取 3D Tiles 要素。

适用于已知 GPS 坐标但需要反查建筑、管线属性的场景。

空白区域（无拾取对象）

拾取方式：scene.pickPosition() 获取屏幕点对应的世界坐标。

转换坐标：Cartographic.fromCartesian() 得到经纬度高程。

适用场景：获取点击位置的地理坐标、查询高程值。

⚠
对于 3D Tiles 要素，建议前端只提取唯一 ID，然后通过 ID 调用后端业务接口获取全量详情，避免将大量业务属性直接挂载到 properties 中造成内存压力。

Module 04

坐标系理解与转换

三维开发中 80% 的"数据位置不对"问题都源自坐标系混乱。本节讲清楚 Cesium 内部使用的坐标体系、GIS 行业常用标准，以及它们之间的转换方法。

Cesium 中的三种坐标体系

坐标系数据类型表示方式典型用途
WGS84 经纬度 Cartographic 经度 (°) / 纬度 (°) / 高程 (m) GPS 定位、用户输入坐标、地理编码结果
笛卡尔空间坐标 Cartesian3 X / Y / Z（单位：米，地心坐标系） Entity 定位、空间距离计算、模型矩阵变换
屏幕坐标 Cartesian2 像素 x / 像素 y 鼠标交互、UI 弹窗定位、拾取操作

GIS 常用坐标系（EPSG 编码）

EPSG名称类型使用场景
4326 WGS 84 地理坐标（经纬度） 全球 GPS 标准；Cesium 内部默认使用的坐标参照系
3857 Web Mercator 投影坐标（米） Google Maps / OSM / 天地图 Web 瓦片；采用正方形切片，高纬度地区变形明显
4490 CGCS2000 地理 地理坐标（经纬度） 中国国家标准（天地图、自然资源部数据），与 WGS84 差异小于 1 厘米
4548 CGCS2000 / 3°带投影 投影坐标（米） 国内测绘、城市规划、工程测量，超图 iDesktop 制图常用

超图工具链中的坐标系处理

iDesktop（桌面端）

数据入库时需设定坐标系。测绘数据多用 CGCS2000 (4490/4548)，互联网数据多用 WGS84 (4326)。坐标系在此环节确定，后续流程必须保持一致。

iServer（服务发布）

发布三维服务时可配置动态投影。REST 接口返回的坐标默认与数据源相同，也可在请求参数中指定 prjCoordSys 进行动态投影转换。

Cesium 前端加载

Cesium 内部统一使用 WGS84（经度/纬度/高度）和 Cartesian3（地心直角坐标）。CGCS2000 (4490) 与 WGS84 (4326) 差异极小（<1cm），实际使用中可直接当作 4326 处理。

⚠
遇到数据偏移或位置错误，优先检查数据源的坐标系与加载端是否一致。Cesium 所有内部运算均基于 WGS84 (4326)。

核心坐标转换链路

WGS84 经纬度
(lng, lat, alt)
⇄

关键转换 API

经纬度 → Cartesian3

Cesium.Cartesian3.fromDegrees(lng, lat, alt)

最常用的转换，创建 Entity 时必用。

Cartesian3 → 经纬度

Cesium.Cartographic.fromCartesian(cartesian)

返回弧度值，需用 Math.toDegrees() 转成角度。

屏幕坐标 → 世界坐标

scene.pickPosition(screenPos)（考虑地形/模型深度）
camera.pickEllipsoid(screenPos)（仅椭球面）

世界坐标 → 屏幕坐标

SceneTransforms.wgs84ToWindowCoordinates(scene, cartesian)

用于在 3D 物体上方准确叠加 HTML 弹窗或 UI 元素。

Module 05

问题排查与调试

白屏、黑屏、模型飘在半空、瓦片加载失败——这些"经典故障"每个人都会遇到。掌握调试工具和方法，10 分钟定位问题远胜于 2 小时盲目猜测。

核心调试工具组合

Cesium Inspector（通用场景）

viewer.extend(Cesium.viewerCesiumInspectorMixin)
可查看地形渲染状态、深度缓冲、拾取信息、Primitive 包围盒。通用场景调试首选。

3D Tiles Inspector（瓦片专用）

viewer.extend(Cesium.viewerCesium3DTilesInspectorMixin)
专门针对 3D Tiles 数据集：查看瓦片树结构、LOD 层级、内存占用，并可可视化包围盒与线框。

浏览器 Network 面板

过滤 b3dm、i3dm、terrain 等关键字，观察请求数量、响应时间、HTTP 状态码（404/CORS 等）。

Console 控制台

使用 viewer.entities.values 列出所有 Entity；viewer.scene.primitives 查看 Primitive 集合；viewer.camera 获取当前相机位姿参数。

💡
超图定制版差异：超图 Cesium 中对应的调试器为 SuperMap3D.Cesium3DTilesInspector，类名不同但用法类似。

常见症状与排查方向

症状可能原因排查方向
白屏（无任何渲染）WebGL 上下文丢失检查 GPU 驱动 / 浏览器硬件加速设置
黑屏（有控件但无底图）影像服务未响应或 Token 失效Network 面板查看影像请求的 HTTP 状态
模型悬空或浮在空中未设置 heightReference 或高度偏移错误设置为 CLAMP_TO_GROUND 或调整高度值
模型沉入地下地形精度与模型高度不匹配检查 modelMatrix 或增加高度偏移
跨域错误（CORS）资源服务器未配置跨域响应头服务端添加 Access-Control-Allow-Origin: *
瓦片闪烁或加载缓慢SSE 值过小 / 网络瓶颈适当增大 maximumScreenSpaceError 参数
帧率极低Entity 数量过多 / 未开启按需渲染改用 Primitive 批量渲染，开启 requestRenderMode

Q & A

答疑环节

"这个功能能不能实现？"

能，关键看数据量大小和数据格式是否支持。

"数据加载出来但位置偏了？"

先检查坐标系是否一致，再确认参数输入顺序（经度在前）。

"帧率很低，操作卡顿？"

Entity 数量过多请改用 Primitive，或适当调大 SSE 值以降低细节。
